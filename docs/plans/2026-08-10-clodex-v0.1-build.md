# Clodex v0.1 Implementation Plan (build → pilot → release)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build, pilot, and release clodex v0.1 — the core-path workflow skill set specified in `docs/clodex-design.md` (Codex-plan-review APPROVED, 3 rounds).

**Architecture:** Shared state engine and Codex runner first (they are the load-bearing contracts), then five skills that consume them, then a real-feature pilot in a personal repo, then catalogue release. Every contract referenced below is defined verbatim in the spec — tasks cite its sections rather than restating them; the spec is the single source of truth.

**Tech Stack:** Claude Code skills (markdown), Python 3 (state engine + validators, stdlib only), bash (runner), JSON Schema.

## Global Constraints

- Spec is authority: `docs/clodex-design.md`. Where a task and the spec disagree, the spec wins and the task gets fixed.
- Public repo: no client names, no vault paths, no study excerpts anywhere in `skills/` or `docs/`.
- Never stage repo files outside this plan's paths (`skills/clodex*`, `docs/`) — the repo may carry unrelated WIP.
- Skill frontmatter: trigger-only descriptions ("Use when…"), no workflow summaries (writing-skills SDO rule).
- Python: stdlib only, one focused file per responsibility. Bash: no shell-string prompt transport, ever.
- Commits after every green task; `Co-Authored-By: Claude` trailer per house style.

## Milestone A — Shared infrastructure

### Task 1: State engine (`clodex_state.py`)

**Files:**
- Create: `skills/clodex/state/clodex_state.py`
- Create: `skills/clodex/state/schemas/event.schema.json`, `snapshot.schema.json` (fields exactly as spec §Run state)
- Test: `skills/clodex/state/test_clodex_state.py`

**Interfaces:**
- Produces: `append_event(run_dir, event: dict) -> int` (returns seq; fsyncs before returning), `rebuild(run_dir) -> dict` (deterministic reducer), `load_snapshot(run_dir) -> dict` (validates, falls back to rebuild), `acquire_lock(run_dir) -> Lock` (raises `RunLocked` with holder info), `atomic_write_snapshot(run_dir, snap)`.
- CLI: `python3 clodex_state.py {append|rebuild|status} <run_dir>` for skill use.

- [ ] **Step 1: Write the failing tests** — the contract tests from spec §Run state:

```python
def test_seq_monotonic_and_fsynced(tmp_path):
    s1 = append_event(tmp_path, {"e": "run:opened"})
    s2 = append_event(tmp_path, {"e": "stage:plan:entered"})
    assert (s1, s2) == (1, 2)

def test_torn_final_line_truncated(tmp_path):
    append_event(tmp_path, {"e": "run:opened"})
    with open(tmp_path / "events.ndjson", "a") as f:
        f.write('{"schema_version":1,"seq":2,"e":"stage')  # torn write
    snap = rebuild(tmp_path)
    assert snap["last_seq"] == 1          # torn line dropped, logged

def test_reducer_deterministic(tmp_path):
    for e in ["run:opened", "stage:plan:entered", "plan:approved"]:
        append_event(tmp_path, {"e": e})
    assert rebuild(tmp_path) == rebuild(tmp_path)

def test_second_writer_blocked(tmp_path):
    with acquire_lock(tmp_path):
        with pytest.raises(RunLocked):
            acquire_lock(tmp_path)

def test_invalid_snapshot_falls_back_to_rebuild(tmp_path):
    append_event(tmp_path, {"e": "run:opened"})
    (tmp_path / "run.json").write_text("{corrupt")
    assert load_snapshot(tmp_path)["stage"] == "open"
```

- [ ] **Step 3:** Implement `clodex_state.py`: NDJSON append with `os.fsync`, seq from last valid line; reducer applying spec invariants (stage monotonicity, one open release step, approvals reference existing plan hashes — violation ⇒ `ReducerInvariantError`); lockfile with PID + ISO timestamp; snapshot via temp-file + `os.replace`.
- [ ] **Step 4:** `pytest skills/clodex/state/ -v` → PASS.

Frontmatter descriptions are trigger-only.

**Interfaces:** Produces the profile (spec §Repo profile, incl. structured action policy with `auto-with-authorization` / `always-ask-exact`) and run-open protocol consumed by every stage skill: router opens the run dir, records `git.start_head` + `dirty_at_start`, acquires the lock.
