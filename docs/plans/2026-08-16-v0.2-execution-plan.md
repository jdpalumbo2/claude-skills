# clodex v0.2 — execution plan

Written 2026-08-16; executed the same day. **Status: all six phases complete** —
tags `clodex-v0.2.0` (phases 1–2), `clodex-v0.2.1` (phase 3), `clodex-v0.2.2`
(phase 4), `clodex-v0.3.0` (phases 5–6). Final suite: 45 exploit+control checks,
17 runner cases, 78 engine contract tests, all green (`tests/run.sh`).

This plan came out of clodex's first major project: a five-lane orchestrated
build in a private pilot repo (worktree-per-lane, an orchestrator session
briefing and gating each lane, ~20k merged lines in ~36 hours). The full
review, deep-dive analysis, and the executed copy of this plan with its
per-task log live in that private workspace; this public copy keeps the
engineering record with the pilot's identifying details removed. Commit
messages in this repo reference the task ids below.

## Ground rules the execution followed

1. **No new event names.** The 23-name vocabulary in
   `skills/clodex/state/schemas/event.schema.json` survives v0.2 intact:
   everything landed as fields on existing events, new `approval:granted`
   scope strings, enum value additions, free-string preflight check names, and
   profile keys.
2. **The reducer whitelists are the trap.** Fields on events whose handlers
   copy generically (`preflight`, `codex` telemetry) are free. Fields on
   `finding:recorded`, `run:opened`, and `release:updated` are whitelisted in
   `skills/clodex/state/reducer.py` — a field added to a schema but not to the
   handler tuple is silently inert. Every schema field addition below named its
   reducer edit.
3. **Amend prior rulings in the same commit that reverses them.** `handed-off`
   reverses `v0.2-debt.md` closed ruling 1; the typed mandate carves into
   `clodex-design.md`'s "Human-owned decisions" list. Both landed with the
   prior document amended in the same commit.
4. **Exploit + control for every engine/runner change** — each behavioral fix
   shipped with a check reproducing the old failure and one proving the fix.
5. **Pathspec commit discipline** throughout; never `-A`/`.`/`-a`.

## Phase 0 — Preserve and reconcile (private pilot workspace) — DONE

Executed in the pilot repo, not here: the five lanes' run-state core (event

`.clodex/archive/`, the five lane reports that existed only as chat messages
were extracted verbatim from session transcripts, and the repo's forked
profile (two independent first-run interviews had produced contradictory

## Phase 1 — clodex-plan overhaul (prose-only; the #1 quality fix)

The pilot's most expensive failure: a lane built a polling transport while the
proven job-runner pattern for the identical product shape sat live in the same
repo — five plan-review rounds and 28 findings never surfaced it, because
nothing *owned* the question.

- [x] **1.1 Required `## Prior art` section.** §5 template, directly after
  `## Grounding`: the plan must name the existing mechanism in this repo that
  solves an isomorphic problem, **cited by path**, and say why it is or is not
  the shape used. "None exists" is legal only after stating where you looked.
  Cross-referenced with §4's tie-break; §3 notes prior art is resolved by
  reading, never by asking the user. (Both §2.3 and §8 check 2 already carried
  this as prose duty and the pilot proved prose duty fails — the fix is a
  witnessed, hashed artifact the reviewer must interrogate.)
- [x] **1.2 Release-owned set beside the Batches table** (debt #9): §5 prints
  the profile's `version.source`, `changelog.path` file(s), and tag machinery
  next to the batches, mirroring clodex-build §2's derivation — a plan once
  assigned the changelog and version source to a build batch and survived six
  review rounds; it died at the first line of build.
- [x] **1.3 Required `Docs impact:` line** — whether the change alters anything
  the profile's `docs.architecture` files describe, and which batch owns
  updating them. Closes the gap where architecture docs were read at plan and
  never maintained.
- [x] **1.4 Round-1 reviewer prompt interrogates all three** — prior-art
  isomorphism with repo citations demanded, release-owned overlap, docs impact
  without an owning batch.
- [x] **1.5 Review-loop exit** (debt #1): the `deferred-to-build` disposition
  (operator-owned, for findings that are true but implementation detail; build
  re-surfaces each when its owning batch opens), and the round cap re-keyed to
  the **severity trend** — the exit is a round producing zero high/blocker
  findings after dispositions, not a fixed round count.
- [x] **1.6 Coherence pass** across the state table, required-headings list,
  and common-mistakes table.

## Phase 2 — Engine, runner, and gate correctness

- [x] **2.1 Test harness** (`tests/run.sh` + per-subject suites): synthetic git
  repos in temp dirs, driving `clodex_state.py` and `run-codex.sh`, exploit +
  control per fix. Debt #3 finally closed.
- [x] **2.2 `append` never creates a run directory.** Exit 2 when the run dir
  does not exist (creation belongs solely to the router's §6 `mkdir`), and
  refusal when the resolved path ≠ `<recorded repo>/.clodex/<recorded run id>`
  — during the pilot, an append with a relative RUN_DIR from a drifted cwd
  silently created a stray parallel run directory.
- [x] **2.3 `append -e '<json>'`** inline payload; stdin remains the default.
- [x] **2.4 `boundary-check` verb** with `--baseline` pre-invocation snapshots
  (debt #6): classifies every changed path owned / acknowledged / STRAY,
  replaces the ~20-line loop one pilot lane hand-wrote eight times, and never
  offers a restore for a path the run cannot prove it touched.
- [x] **2.5 `telemetry-sync` verb + duration truth.** Diffs envelopes on disk
  against `codex` blocks in the log and prints orphaned invocations as
  ready-to-attach blocks — seven completed invocations (~1 h of delegated
  work) went unrecorded in the pilot. `duration_s`/`status` are **copied from
  the envelope**, never estimated (logged round-number estimates ran up to
  1.77× actuals).
- [x] **2.6 Append-time finding validation** — no content-free findings, and
  `invocation` required when `source` is a Codex role.
- [x] **2.7 Finding enrichment.** `location`, `detail`, `recommendation` in
  both schemas + the `finding:recorded` reducer whitelist; `finding:disposed`'s
  `note` promoted to the snapshot. The pilot's overturn authority provably
  could not rule from state (one sentence per finding) while every envelope
  carried file:line — the fix is to stop discarding what the runner already
  emits.
- [x] **2.8 Runner hardening.** Envelope written from an EXIT trap
  (INT/TERM/HUP/QUIT trapped, `trap '' PIPE`) — a 27-minute round had died
  envelope-less; heartbeats to the log file; `prompt_file` persisted so bare
  `--resume <id>` works; `--detach` mode replacing nohup folklore; `--run-id`
  keys runner state so two runs in one repo no longer interleave (debt #5).
- [x] **2.9 Gate-evidence discipline.** `${PIPESTATUS[0]}` under `pipefail`
  wherever a gate is piped (the pilot printed `gate rc=0` for a suite that
  died on ENOENT — `$?` captured `tail`); a pass **count** is mandatory beside
  every rc; rebase/merge batches owe a test-inventory **name** diff — a
  conflict resolution silently deleted a regression test and every
  count-based gate stayed green.
- [x] **2.10 Ship §5 validator cut-aware** — a step named in the
  authorization's `cut` list is exempt from the bookkeeping-descriptor demand.

## Phase 3 — The orchestrated-lane shape

The pilot's dominant real usage — brief-to-reviewed-branch with an external
orchestrator owning release — became legal instead of contorted: four of five
successful lanes had been forced to record `release: abandoned` and write
near-identical "by design" prose to compensate.

- [x] **3.1 Profile carrier:** optional top-level `release_owner:
  "run" | "external"` (default `"run"`), no `schema_version` bump — old
  installs degrade gracefully.
- [x] **3.2 `handed-off` terminal state** in the `release.state` enum (the
  reducer derives legality from the schema — no reducer edit), with all three
  ship derivations (§4/§5/§10) taking the same external branch and §10's
  nothing-ran-means-abandoned guard now conditional on the declared shape plus
  a recorded handoff artifact. `v0.2-debt.md` ruling 1 and the design doc's
  exit contract amended in the same commit.
- [x] **3.3 Handoff artifact** — `skills/clodex/templates/handoff.md` (7
  sections: negative-space status line, commits table, merge conditions,
  numbered deploy actions with `<verify>` markers and a negative post-deploy
  test, residuals by finding id, evidence index, run-log pointer); ship writes
  it and records a plan-hash-bound `scope: "handoff"` approval before
  `handed-off`.
- [x] **3.4 Run archival on close** — router §2 recipe copying the run core
  (log, snapshot, manifest-named envelopes, handoff, declared evidence) into
  the main checkout's `.clodex/archive/<run-id>/`; archived, not committed.

## Phase 4 — Multi-lane operations

- [x] **4.1 Bootstrap ritual.** First-run setup happens once, on the default
  branch, from the main checkout, before lanes fork; worktree lanes get a
  `bootstrap` preflight check that *requires* the committed profile instead of
  re-interviewing (kills the profile-fork failure permanently). The nested
  self-exempting `.clodex/.gitignore` is the preferred remedy (debt #2).
- [x] **4.2 Ignore-mechanism sweep.** Preflight probes `.gcloudignore` /
  `.dockerignore` / `.vercelignore` / `.npmignore` — they **replace**
  `.gitignore`, and the pilot's deploy window caught sixteen worktrees of run
  state entering a production build upload.
- [x] **4.3 Worktree provisioning** — preflight *offers* `commands.install`
  and env-file materialization (offer-first, never auto); python-suite
  evidence must include the resolved module path so a parent-venv gate can
  never masquerade as a worktree gate.
- [x] **4.4 Typed mandate.** `approval:granted` with `scope: "mandate"` and a
  grants vocabulary of exactly three (finding-disposition, plan-approval,
  direction-approval); verification-debt acceptance and release authorization
  are excluded and stay human. Plan-hash-bound (re-grant on amendment,
  documented). The design doc's human-owned list amended in the same commit.
  In the pilot, one lane satisfied gates on brief authority while a sibling
  raised a blocking modal for the same gate class — the mandate makes that a
  recorded state, not an improvisation.
- [x] **4.5 Shared-claims ledger.** Committed `.clodex/claims.json`,
  orchestrator-owned, lanes read; a preflight check fails a lane on a held
  claim (three pilot lanes independently claimed the same migration number);
  the sibling-wait Monitor pattern documented as the sanctioned recipe.
- [x] **4.6 Cross-run index.** `clodex_state.py runs <main-checkout>` walks
  the checkout and its worktrees, one status line per run; router §2 re-worded
  to per-**checkout** run scoping with the index as the repo-wide view.

## Phase 5 — Codify the brief and report contract

The pilot proved brief anatomy — not the run machinery — carried output
quality: a bare control lane matched the clodex lanes at merge time because
its brief was equally good, and every report's structure mapped one-to-one
onto its brief's closing `REPORT BACK:` line.

- [x] **5.1 `skills/clodex/templates/lane-brief.md`** — the 16-part anatomy,
  plus the two standing rules: the orchestration plan is committed before
  lanes fork, and every brief requires the lane's report to open with its run
  id — or the word "bare" and why.
- [x] **5.2 `skills/clodex/templates/lane-report.md`** — the common report
  shape (run-id-first status line with explicit negative space, commits table,
  evidence by class with counts vs baselines, residuals by finding id;
  deploy actions delegate to `handoff.md` for external-owner runs).
- [x] **5.3 Router pointer** — the "Orchestrated lanes" subsection.

## Phase 6 — The audit lane

Pre-authorized by the design doc's own entry criterion ("enters only with
usage evidence") — two major audit-shaped asks ran manually during the pilot,
both to excellent results, and their reports are the template. Only audit was
built; repair/chore/sync stay honestly refused.

- [x] **6.1 `skills/clodex-audit/SKILL.md` + README** — read-only charter;
  verdict-first sections; VERIFIED-with-method / HYPOTHESIS tags; a mandatory
  early "Corrections to the prompt's premises" section; an evidence-constraint
  note; three-bucket discipline (candidates ranked by payoff/cost ·
  deliberate-simplicity keeps, so nobody relitigates · locked constraints,
  noted-only); a fixed per-candidate schema; a Surprises section; per-item
  lane routing; insertion-cost sequencing. Stage stays `open`, release stays
  `not-started` — no coupling to Phase 3.
- [x] **6.2 Router integration, same commit** — audit row into the core path,
  noticing rule now names only repair/chore/sync, handoff table routes the
  lane.
- [x] **6.3 Catalogue plumbing** — symlink live, README rows, harness smoke.
